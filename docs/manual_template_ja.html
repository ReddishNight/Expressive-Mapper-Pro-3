表現力マッパー Pro 3

公式ユーザーマニュアル ＆ アルゴリズム仕様書 — Synthesizer V Studio 2 PRO
著者: Nyoru.X
バージョン: v3.6.2 (DOD Engine)
動作環境: SynthV Studio 2 PRO v2.2.1+ (Build 67072)

本マニュアルは 表現力マッパー Pro 3 の完全な技術ドキュメントです。各スクリプト .lua の専用ガイドに加え、実用的な使い方がわかる「簡単な概要」と、高度な制作者向けの「拡張技術仕様」の2段階構成で解説しています。

3.6.2 パッチノート
今回の版では新しいプリセットを増やさず、既存機能の品質を改善しました。
  • Vocal Harmonies: 声部の間隔、レンジ、ボイスリーディング、および ComboBox の選択反映を改善し、より自然な合唱生成に調整しました。
  • Chords: オプションやサブオプションごとの差分が出るように改善しました。
  • UI ステータス: 成功/失敗の表示を共通かおもじに簡略化しました。
  • 言語の永続化: idiomaUI の JSON 保存を削除し、SynthV ホスト言語が古い設定で固定されないようにしました。
  • Apply フロー: Apply ラベルの翻訳漏れを修正し、適用後のメッセージ表示を減らしました。
  • ドキュメント: 現在の 3.6.2 モジュール構成とパッチ内容に合わせて更新しました。

1. インストールと動作環境
簡単な概要 (実用的な使い方)
Synthesizer V Studio Pro に各 .lua スクリプトを導入する手順：
  • SynthV の上部メニューから スクリプト → スクリプトフォルダを開く を選択。
  • 使用したい .lua ファイルを配置。
  • SynthV で スクリプト → スクリプトの再スキャン を実行すると準備完了です。
拡張技術仕様
実行環境と Dreamtonics API との連携：
  • エンジンアーキテクチャ: Lua 5.4 / LuaJIT 環境で動作する独立した SidePanelSection サイドパネル。
  • 設定の保存: ユーザー設定を mapeador_user_config.json に自動保存。
2. スクリプト 1: Expressive_Lyric_Melody.lua (I)
簡単な概要 (ワークフロー)
歌詞を入力し、主音とスケールを選んで、メロディラインを自動生成します。
技術操作仕様
2つの動作モードをサポート：
  • 新規生成モード: 再生ヘッド位置からノートを新規作成。
  • 選択ノート置換モード: 既存ノートの時間的長さとリズムを保ちながら、歌詞を当てはめてスケールに量子化。
3. スクリプト 1: Expressive_Lyric_Melody.lua (II)
簡単な概要 (裏技)
%（例：歌詞です %10 バースです）を使うと指定秒数にノートグループが被らず作成されます。
アルゴリズムおよび韻律分析仕様
スペイン語のアクセント付母音（á, é, í, ó, ú）に対してピッチを+20セント、張力を+15%増加させて自然なイントネーションを生成します。
4. スクリプト 2: Expressive_Vocal_Automation.lua (I)
簡単な概要
ボーカル表現力向上ツール。ノートを選びプリセット（Belting, Sad等）を選ぶと、自動で綺麗なスプライン曲線のオートメーションを描画します。
エルミートエンジンの技術仕様
C1連続のエルミート曲線とTCB制御を用いてピッチやテンションパラメータの急激な変化を防ぎます。
5. スクリプト 2: Expressive_Vocal_Automation.lua (II)
簡単な概要 (裏技)
子音を自動検出して、張力のピークを母音開始位置（vowelOnsetBlick）に自動調整します。
子音同期と RDP 簡素化仕様
RDP（Ramer-Douglas-Peucker）アルゴリズムを用いて不要な制御点を間引き、CPUやプロジェクトへの負担を軽減します。
6. スクリプト 3: Expressive_Harmonies.lua (I)
簡単な概要
コーラス生成ツール。主旋律ノートを選び、ハモリプリセット（SATB、3度ハモリ等）またはカスタム音程（+3, -5, c+7等）を指定します。
ダイアトニックハモナイザー仕様
メイングループの timeOffset と timeRange を新規生成するハモリトラックに継承し同期させます。
7. スクリプト 3: Expressive_Harmonies.lua (II)
簡単な概要 (裏技)
ハモリが重なって機械的なコーラス効果になるのを防ぐため、ガウス分布によるわずかなピッチ・時間的ズレ（デチューン）を適用します。
純正律調律と AI リテイク仕様
純正律（Just Intonation）を有効にすると、Major 3rdを -13.69 セント、Minor 3rdを +15.64 セント調整して完全なハモりを作ります。
8. スクリプト 4: Expressive_Chords.lua (I)
簡単な概要
コードバッキング自動生成。再生位置を選び、進行スタイルとリズムを選んで適用すると、Voice Leading を計算した伴奏ノートを作成します。
和声 Voice Leading 技術仕様
前のコードからの音程変化距離（エネルギー総和）を最小にする和音転回アルゴリズムを搭載。
9. スクリプト 4: Expressive_Chords.lua (II)
簡単な概要 (裏技)
独立した対位法副旋律（フックス第1〜3種）を生成して、メインの歌声の邪魔をしない伴奏を作れます。
対位法＆リズム仕様
連続5度・連続8度の禁止規則を計算し、リズムには5%〜20%の微細スウィングを挿入します。
10. モード 0: 韻律分析と自動歌声表現
簡単な概要 (実用的な使い方)
歌詞に基づいてピッチとテンションを自然に変更します。
拡張技術仕様
Krumhansl-Kessler 調性検出を用いて自動でスケール主音を判定。

調性検出のピアソン相関係数式:

r = Sum((H(i) - H_prom) * (P(i) - P_prom)) / Sqrt[ Sum((H(i) - H_prom)^2 * Sum((P(i) - P_prom)^2) ]
11. モード 1: エルミート曲線 / TCBスプライン自動化
簡単な概要 (実用的な使い方)
パラメータの急激な変化を防ぎ、スムーズなカーブを描画します。
拡張技術仕様
TCBスプラインの数式を用いて Tension (T), Continuity (C), Bias (B) を制御。
P(t) = (2t^3 - 3t^2 + 1)P0 + (t^3 - 2t^2 + t)M0 + (-2t^3 + 3t^2)P1 + (t^3 - t^2)M1

RDP削減およびTCBスプラインの図:

[RDP点の削減とTCB接線ベクトル] 元の曲線: (ノード 1)●───●(ノード 2)───●(ノード 3)───●(ノード 4)───●(ノード 5) RDP削減後: (ノード 1)●───────────────────────●(ノード 4)───●(ノード 5) (許容値 0.2%): 重複する不要なノード 2 と 3 を削除し、CPU負荷を軽減。 TCB接線制御: 残った各ノードの入力/出力接線方向をスムーズに調整。
12. モード 2: ボーカルハーモニーと純正律
簡単な概要 (実用的な使い方)
ハモリパートを作成します。純正律調律でうなりのない美しい共鳴を作成。
拡張技術仕様
純正律比（Major 3rd -13.69c, Perfect 5th +1.96c）への周波数変換。

ガウス確率密度関数（アンチフェーズのズレ量計算）:

f(x) = (1 / (sigma * Sqrt(2 * pi))) * e^( - (x - mu)^2 / (2 * sigma^2) )

ガウス分布によるアンチフェーズ遅延とデチューンの図:

[ガウス分布によるタイミングおよびピッチのオフセット] メイントラック: [--- ガイド音符 ---] (基本位置) ハモリ 1 (L): [--- ズレた音符 ---] (t = -8ms, pitch = -4 cents) ハモリ 2 (R): [--- ズレた音符 ---] (t = +12ms, pitch = +3 cents) AIテイクバリエーション: 各ハモリトラックで Note.getRetakes():generateTake() を再実行。
13. モード 3: 厳格なフックス対位法
簡単な概要 (実用的な使い方)
クラシックの対位法規則に準拠した伴奏パートを作成。
拡張技術仕様
3度と6度を優先し、平行5度・平行8度を禁止する評価マトリクス。

フックス厳格対位法第二類（2:1）の対位旋律作成例:

[対位法第二類 - 各声部の動き] 定旋律 (ガイド): C4 (全音符) ────────────────────> E4 (全音符) 対位旋律 (2:1): E4 (二分音符) ──────> G4 (二分音符) ──> B4 (二分音符) 音程関係: 3度 (協和音) 5度 (経過音) 5度 (経過音) 声部の進行: 反進行 直進行 反進行 強拍における平行5度および平行8度の進行は自動的に回避・禁止されます。
14. モード 4: コード進行・同期・スケール量子化
簡単な概要 (実用的な使い方)
コードバッキング進行を自動作成し、主旋律との時間的ズレや量子化を解決。
拡張技術仕様
Voice Leading 最適化エネルギー数式：
E_total = Sum [ P_nuevo(v) - P_previo(v) ]^2

最小エネルギーによる連結和音（ボイスリーディング）の図:

[和音ボイスリーディングの最適化] 和音 Cmaj7 (I): G4 (ソプラノ) ──── B4 (アルト) ───── E5 (テナー) │ (差分 = 0) │ (差分 = +1) │ (差分 = 0) 和音 Am7 (VI): G4 (ソプラノ) ──── C5 (アルト) ───── E5 (テナー) 総エネルギーコスト = (0)^2 + (1)^2 + (0)^2 = 1 (スムーズな最適反転！)

16. 静的バッファ構造 (DOD) とメモリ最適化
簡単な概要 (実用的な使い方)
Synthesizer V 内での実行時にメモリ(RAM)やCPUの消費を極限まで削減。
拡張技術仕様
Lua/LuaJIT のガベージコレクション(GC)によるオーディオ処理の遅延を防ぐため、評価用バッファ（EVAL_NODOS等）を静的に事前確保。
